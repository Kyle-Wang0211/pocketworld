## 一句话判决

- **R2 guided matching(D 臂):NOT_LOSSLESS,决定性。** 每对 verified ×2.8(135→376,与侦探 ×3.12 对账)、注册 31→34、点数 ×1.84,
  但 9 条交付指标在噪声带外更差:track 均值 −8.2%、≥3 观测占比 0.844→0.640、重投影 +4.5%/点级中位 +6.4%、浮点风险占比 ×5.9、

  劣化不来自多注册的 3 帧(只看 A 也注册的 31 帧内的点,孤立占比仍 9.05% vs 1.3%)——是 guided 匹配本身在造短 track 孤立点。

### 0.3 预算 clamp 语义:pycolmap 组边界 ≠ 设备精确切

pycolmap `max_num_features`(COLMAP covariant 路 `sift.cc` 语义)只在 (octave,scale) 检测层级的组边界停,超预算最多一个组 ——
实测 8192 臂的 7 张饱和图实际保留 **8196-11014**;设备 `official_dsp_sift_gpu_c.cc:235-278` 用同一比较器排序后**精确切到 8192**
(设备 db keypoints rows 全 = 8192)。db 行序即 COLMAP 排序后顺序(粗→细,已核:饱和图行序首尾晶格 k=24-28 → 0-6),截前 N 行 = 设备 clamp
(`clamp_db.py`,已验证 7 图截取为严格前缀、keypoints/descriptors 逐字节等于原前 N 行)。
因此**主判决臂用精确 clamp**(A_exact/B_exact/D_exact);组边界臂(A_fo0/B_fo0/D_fo0)保留作敏感性行。C(16384)两种语义相同(无图超 16384)。
精确 clamp 使基线更贴设备:A_exact 点数 6062 vs 组边界 A 6259(−3.1%),每对 verified 中位 135 vs 128。

## 4. 机制解释

### 4.1 升预算是否真把 octave 0 捞回来(`runs/cap_1784809021393372/mechanism_exact.log`)

- A(8192 精确 clamp)打满的 7 帧(frame 14/15/20/25/29/30/34),特征集是 C 的严格前缀(A⊆C 命中 8192/8192)。
  被预算裁掉的特征合计 **22,185**:43% 尺度<2.54、74% <3.20;按晶格 σ=1.6·2^(k/3):k0:340 k1:5408 k2:7597 k3:5053 k4:2221 k5:1059
  → **k0-k2(σ 1.6-2.54,octave 0)占 60%**。7 帧的最细存活尺度 A=1.80-2.27 → C=1.60-1.61(octave 0 底层回来了)。
  全池 scale<2.54 占比 A 0.135 → B 0.159 → C 0.161(B≈C:13312 只在 1 帧触发)。
- **但本场景裁得比 build89 浅**:build89 每图最细存活尺度中位 2.54(51f)/3.20(20f)= octave 0 整族没了;本场景 7 帧只裁到 1.80-2.27,
  且 30/37 帧根本不裁。所以"捞回 octave 0"在这里只发生在 7 帧的底层,重建层的体现就只有点数 +7%、总内点 +6%、
  **每对 verified 中位持平(135→132→134,gap-1 339→344→338)** —— 侦探的 +37~100% 是全饱和体制的估计,本场景测不到。
- 升预算改变 NN 竞争(侦探警告"新特征可当 2nd-NN 杀死旧匹配")的迹象:每对 raw 中位 80→75(−6%),但 verified 总内点仍 +6%;
  重建层没有任何噪声带外的损失 —— 在部分饱和体制下这条风险没有显形。

### 4.2 guided 新增的匹配落在什么尺度/位置(同一 extract.db,D_exact rep0 vs A_exact rep0)

- D 的 TVG 内点里 **66% 不在 A 的内点集**(逐对中位;gap-1 54%、gap≥2 66-71%);总内点 34,746 → 67,161。
- 新增匹配 keypoint 尺度 p10/p50/p90 = 2.23/4.75/12.96(A 基线内点 3.06/5.33/11.82);**尺度<2.54 的占比 15.6% vs 基线 4.0%** —— guided 主要把
  ratio 检验杀掉的细尺度对应捞回来(与侦探 §2.6"描述子空间拥挤"的机制一致)。
- 位置:到图像中心距离中位 **725 px vs 基线 526 px**;图像域 k=8 近邻距离中位 **111 px vs 基线 44 px** —— 新增匹配**更外围、更稀疏**,
  **不是**挤在重复纹理密集区的"第 N 根木纹"模式(那种模式会表现为新增匹配近邻距离更小)。08-11 判死的是引导链第二级(ARKit 位姿自举),
  这里测的第一级失效形态不同:不是同一根木纹的邻居互串,而是外围/斜视角的细尺度对应过了外极带却三角化成短 track 孤立点。
- 劣化归因(`probe/d_isolated_origin_exact.log`):D 多注册 3 帧(image_id 26/27/33),但只看 track 完全落在 A 也注册的 31 帧内的
  11,103 个点:孤立占比 **9.05%**(A 1.3%)、track 均值 3.16(A 3.44)、≥3 占比 0.646(A 0.844)、点级重投影中位 1.244(A 1.171)。
  ⇒ 劣化来自 guided 匹配本身,不是多注册帧;孤立点里含多注册帧的只占 4.7%。
- 与 08-11 先例的对应:当年 achieved 101/101 注册 + 净增 935 孤立浮点、P@2cm 99%→85%;这里注册 31→34 + 孤立点 80→973、
  2-view 占比 ×2.3、重投影 +4.5%。"inlier 数不是交付质量"再次成立。

## 5. 局限(如实)

1. **主机 CPU covariant SIFT ≠ 设备 GPU DSP-SIFT**。逐帧计数 r=0.995、饱和集合同一批帧是提取侧对齐的证据,但描述子/定位不是逐位的;
   侦探 §2.3 量过设备提取器不劣于 COLMAP CPU。本审计证的是"预算/guided 这个变量在重建层的方向与量级",不是设备绝对值。
2. **只覆盖部分饱和体制**:两场都只有 7 帧触发 8192、1 帧触发 13312、0 帧触发 16384。build89 的 20/20 全饱和(octave 0 整族被裁,最细存活 2.54-3.20)
   没有照片,无法复现;**R3 在那个体制里的收益与风险本审计都没测到**,不能外推。父任务字面口径(fo=-1)能制造"全帧饱和",但特征是
   设备从不产生的上采样八度(89k-99k/图),作为代理没有机制意义,且组边界语义下暴力匹配要数小时,已启动后掐掉(`runs/*/A_fo-1`、`C_fo-1` 为残件)。
3. **场景**:两场都是 ~0.5 m 盒内近拍小物体(相机-点距中位 0.16 m)、手动 tap 采集(179/366 对 raw<15);注册 31/37、13/25(场景 2 裂成 13+11 两个子模型)。
   不是房间尺度、不是自动拍轨迹。
4. **管线不是产品核**:pycolmap 4.0.4 默认建图(非流式核)、sequential 12(无空间候选、无回环)、plain COLMAP TVG(非 mandatory-gravity)、
   单相机中位内参 + BA 默认精调焦距;frameId 29 照片在备份中缺失(基线毁片 bug 的已知产物),时序在此处有一格跳。
5. **耗时只作相对**:主机暴力匹配 wall 有 ±30% 的跑次波动(A_exact 2689 vs A_fo0 2024 ms/对),分辨不出预算带来的 GEMM 差(中位帧 6123 特征三臂相同,
   只有 7 帧的对变贵);热/队列/每张毫秒对照是真机的事。
6. **精确 clamp 是仿真**:截 COLMAP 排序后前 N 行;设备组内顺序假定同为检测顺序,未与设备逐位对拍(设备 db 是 07-23 旧核,无同帧现役提取可比)。
7. **D 只有 2 rep**(每 rep 8.5 分钟);其劣化幅度是噪声带的 10-50 倍,够判;但 D 的 guided 半径/带宽只测了 COLMAP 默认(max_error 4px)。
8. **浮点风险口径**(视差角<3°&track<3)在 COLMAP 默认建图后天然稀少(min_tri_angle 1.5° + 忽略 2-view track 已先过滤),绝对数 2-22;
   信号主要由几何孤立(k8 近邻)口径承担 —— 这正是研究仓 isolation_check.py 注释里说的那种情况。
9. **未测**:米制尺度、P@2cm(无 ground truth;ARKit 光心只用于 gauge 统一,残差 5mm/2mm 中位,不当精度尺子)。
