# PocketWorld 个人主页、关注、举报与拉黑设计规格

**状态：** 用户于 2026-08-29 批准第五版原型，允许进入实现与装机流程。

## 目标

把社区作者从“可过滤的名字”升级为真实社交主体：用户可从任务卡作者名进入个人主页，关注或取消关注，在“我的”页面查看关注列表，并在他人主页举报或拉黑该用户。举报必须进入可人工受理的后台队列，并支持必要的补充文字与图片证据。

## 已批准的界面

### 社区入口与个人主页

- 点击社区任务卡中的作者昵称或 `@handle`，进入该作者的个人主页，不再切换为作者过滤条。
- 左上角仅显示返回箭头，不在返回按钮后重复显示 `@handle` 或昵称。
- 右上角使用小尺寸横向三点按钮；点击后在按钮下方、屏幕右上区域弹出锚定菜单，不使用底部抽屉。
- 主页显示头像、昵称、`@handle`、IP 属地、简介和一个主操作按钮。
- 他人主页主按钮为“关注 / 已关注”；自己的主页不显示关注自己的按钮。
- 数量区依次显示“作品、粉丝、关注”。“作品”严格表示公开作品数量，不是草稿数或全部云端记录数。
- 公开作品网格直接开始，不显示“公开作品”标题、标签页或下划线。
- 作品网格仅展示 `visibility = public` 且未被平台移除的作品；点击作品进入既有作品详情页。

### 我的关注列表

- “我的”页面增加自己的社交资料摘要和作品/粉丝/关注数量。
- 点击“关注”数量进入“我的关注”列表。
- 列表显示头像、昵称、`@handle` 与关系按钮；可取消关注，也可点整行进入对方主页。
- 空状态使用“还没有关注任何人”。加载失败可重试，不泄露 PostgREST/JWT 等内部错误。

### 右上角菜单、举报和拉黑

- 他人主页三点菜单只有“举报该用户”和“拉黑该用户”。自己的主页不出现这两项。
- 举报一级原因固定为九类：
  1. 冒充他人或账号资料虚假
  2. 骚扰、网络暴力或人身威胁
  3. 诈骗、广告骚扰或异常账号行为
  4. 涉及未成年人安全
  5. 色情低俗
  6. 暴力、自伤、仇恨、极端或其他违法有害信息
  7. 虚假不实或误导性信息
  8. 隐私、人肉搜索、肖像或知识产权
  9. 其他 / 不确定
- 选择原因后进入补充信息页，可填写最多 500 字说明；自动关联被举报用户及当前来源作品（若从作品进入）。
- 普通类别可从系统相册选择最多 3 张 JPG/PNG 图片。客户端解码后重新编码，移除 EXIF/GPS，单张上传后不超过 5 MiB，最长边不超过 2048 像素。
- 涉及未成年人色情、非自愿私密内容等敏感材料时，不要求用户重新上传或传播材料；界面提示平台会保全被关联的站内内容。
- 图片由认证 Edge Function 复核实际字节、尺寸和元数据缺失后存入私有 `report-evidence` bucket；对象路径由服务端生成并绑定举报人和举报编号。举报人只能读取自己的举报记录，管理员通过短时签名 URL 查看证据。
- 举报提交失败必须明确告知；如果举报文字已入队但部分图片上传失败，保留举报并明确提示“举报已提交，部分图片未上传”。
- 拉黑确认文案说明：当前账号登录 PocketWorld 时，不再在社区、搜索、关注列表和个人主页看到对方；双方关注关系立即解除，双方不能再次关注；不会通知对方。公开链接、未登录访问或其他账号仍可能看到其公开内容。
- 用户可在设置中查看已拉黑名单并解除拉黑；解除后不自动恢复关注关系。

## 数据与权限

- `follows` 继续使用 `(follower_id, followee_id)` 复合主键。关注写入必须同时拒绝“我拉黑了对方”和“对方拉黑了我”两种关系。
- “我的关注”通过窄投影的 `get_my_following` RPC 读取，允许返回已经关注的私密账号，但不放宽其他人枚举私密资料的权限。
- 拉黑写入继续触发双向取消关注；所有第一方客户端社交流程均使用同一份拉黑查询结果过滤。
- `profiles.works_count` 的语义迁移为“已发布、公开且审核状态为正常的作品数”，并在作品新增、删除、发布时间、可见性或审核状态变化时维护。
- 举报原因存稳定英文代码，界面文案由本地化层提供。
- `reports.target_type = user` 的队列必须能解析被举报用户资料，显示补充文字、来源作品和私有证据。
- 管理端允许进入审核、驳回或标记已处置，并记录审核人、时间、备注和审计日志。任何账号级处罚必须由人工明确执行；举报数量本身不自动封禁账号。
- 证据对象不公开，不写入分析日志，不暴露原始本地文件名；管理员访问使用短时签名链接。

## 非目标

- 本期不实现私密账号关注申请、粉丝移除、推荐关注、私信或自动封号模型。
- 不承诺在公开存储 URL、未登录网页或其他账号中全局隐藏被拉黑用户；当前承诺只覆盖登录后的第一方 PocketWorld 产品界面。
- 不把举报分类宣称为法规目录逐字翻版；九类是面向用户的产品分类，后台可映射到多条规则。

## 验收标准

- 社区卡作者点击必定导航到个人主页；旧的作者过滤条不再出现。
- 关注、取消关注、计数刷新、我的关注列表、进入关注者主页均有自动化测试。
- 主页返回栏无重复用户名；三点按钮尺寸与位置符合第五版原型；菜单锚定右上角。
- 作品数与公开作品查询一致；未发布、审核中、私密或已移除作品不计数。
- 九类举报原因、500 字限制、最多三图、图片重编码和敏感类别禁上传有测试。
- 用户举报在管理端能看到用户资料、文字和证据；处理动作留下审计记录。
- 双向拉黑均阻止关注，拉黑立即取消双向关注，解除拉黑不自动恢复。
- 所有新增 Flutter 测试、Deno 测试、静态检查与 iOS Release 构建通过。
- 生产 iPhone 只允许在备份和哈希验证成功后通过 `devicectl device install app` 原位更新；绝不卸载生产 bundle。
