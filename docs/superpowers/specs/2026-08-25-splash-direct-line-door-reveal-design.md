# 启动粒子直接归线与双门揭幕设计

日期：2026-08-25

## 目标

在 PocketWorld 的最终启动加载完成时，把当前居中的实时白色 `solving` 粒子球连续变形成一条贯穿屏幕上下的极细白线，再让黑色遮罩像两扇门一样从中央向左右打开，露出已经完整就绪的社区主页。

本变更是现有 `2026-08-25-splash-solving-orb-design.md` 的退出动效增量。它不改变启动加载条件、认证状态、社区数据加载、3D 渲染器初始化或生产算法。

## 已确认的视觉时序

1. 加载期间继续显示现有纯黑背景与屏幕几何中心的 `128pt` 白色实时粒子球，速度保持 `0.8`。
2. 最终加载完成后，取消旧的整页 `420ms` 淡出，不添加全屏发散阶段。
3. 同一批粒子从当前球体位置开始，在 `500ms` 内直接归线：
   - 每个粒子的横坐标连续收拢到屏幕几何中央；
   - 每个粒子的纵坐标同步铺展到整个屏幕高度；
   - 离散粒子在末段逐渐熔合为实体白线；
   - 过程中不消失、不切镜、不更换视觉主语。
4. 最终白线总宽度为两个物理显示像素，而不是两个 Flutter 逻辑像素。每一侧门扇持有一个物理像素的白色内边。实现根据 `devicePixelRatio` 计算 hairline 宽度。
5. 白线保持 `110ms`，确保用户能明确感知粒子已经归线。
6. 两扇纯黑遮罩在 `680ms` 内从屏幕中央向左右移出：左扇携带右侧 `1px` 白边，右扇携带左侧 `1px` 白边。
7. 社区主页从中央缝隙真实露出；主页本身不做淡入、缩放、模糊或位移。
8. 门扇完全离屏后，退出遮罩从组件树移除，恢复底层页面的系统栏样式和输入。

总退出时长为 `1290ms`：`500ms` 归线 + `110ms` 停线 + `680ms` 开门。

## 方案比较

### 方案 A：全屏粒子画布加两扇真实遮罩（采用）

把现有粒子数学复用于全屏 `CustomPainter`。正常阶段仍在中央画 `128pt` 粒子球；退出阶段冻结收到完成信号时的粒子相位，将每颗粒子插值到中央纵线。归线完成后由左右两个黑色遮罩接管相同的白色边界并向两侧平移。

优点：每一颗粒子的轨迹连续；白线到门边可以做到逐像素无缝交接；底层社区主页始终是真实页面；纯 Flutter、无新增依赖。缺点：需要把当前只绘制方形球体的 painter 扩展为全屏序列，并严格管理一个共享时间源。

### 方案 B：保留粒子球，使用中央 `ClipRect` 扩张揭幕

让社区主页的可见裁剪区域从中央向两侧扩大，并在裁剪边缘画白线。

优点：实现短、测试容易。缺点：视觉上是主页被裁剪展开，不是粒子变成门；粒子与门缝之间必然发生接力或淡出，不满足“同一批白色小球直接归线”的要求，因此不采用。

### 方案 C：Metal 或 Fragment Shader 单管线

在 GPU shader 中同时模拟粒子、归线和遮罩揭幕。

优点：可以完全统一渲染管线。缺点：为约两百个启动粒子引入原生 shader、平台接线和额外生命周期风险；当前纯 Flutter Canvas 足以在手机上流畅绘制，也会扩大生产装机验证面，因此不采用。

## 组件与状态边界

### `AetherSplashOverlay`

继续拥有全屏遮罩、输入拦截、系统栏样式和退出生命周期。新增显式退出样式：

- 认证外层启动遮罩保留现有 `420ms` 淡出，不播放双门，避免已登录冷启动时先打开到另一层黑色加载页；
- `HomeScreen` 覆盖在 `AetherAppShell` 上的最终加载遮罩使用 `directLineDoor`，只在真正露出社区主页的最后一次退出播放；
- `visible` 在退出进行中重新变为真时，立即恢复完整黑色遮罩并重新进入粒子球阶段，不泄露半开的底层页面。

### 全屏粒子序列

新增一个只负责视觉的全屏粒子组件。它复用 `buildSplashSolvingParticles` 的确定性球体位置，使用单一时间源，并在退出开始时冻结当前求解相位。它接收：

- 当前求解时间；
- 归线进度；
- 可用全屏尺寸；
- 颜色与速度；
- 是否减少动态效果。

粒子到纵线的分配按稳定粒子序号完成，保证每帧和每次测试确定。末段实体线的 alpha 随归线进度上升，同时粒子 alpha 下降，视觉上是“熔合”而不是突然覆盖。

### 双门遮罩

双门是两个各占屏幕一半的纯黑组件。每扇门只画中央侧的一个物理像素白边。开门阶段只改变水平位移；不使用透明度，避免黑色门扇变灰或提前看到底层内容。

## 数据流与错误处理

1. 现有启动状态继续决定 `visible`。
2. `HomeScreen` 最终加载遮罩第一次收到 `visible == false` 时冻结粒子相位并启动 `1290ms` 退出控制器。
3. 前 `500ms` 只绘制粒子归线；接下来的 `110ms` 保持实体 `2px` 线；最后 `680ms` 隐藏粒子画布并移动双门。
4. 动画结束后移除遮罩、停止 ticker、释放 painter 与 controller，并将系统栏交还底层社区主页。
5. 如果组件在退出期间销毁，所有 controller 和 ticker 都在 `dispose` 中停止，不留下后台重绘。
6. `MediaQuery.disableAnimations == true` 时保留现有静态代表粒子帧；加载完成后不播放归线或开门，直接移除遮罩并恢复底层系统栏，避免强制大范围运动。

## 测试与验收

### 自动化测试

- 先写失败测试，证明最终遮罩不再采用 `420ms` 淡出，而是按 `500/110/680ms` 三阶段退出。
- 验证归线开始时的粒子位置与该时刻球体位置完全一致，没有第一帧跳变。
- 验证归线末帧所有粒子的横坐标都位于中央 hairline 范围内，纵坐标覆盖屏幕上下。
- 验证实体线总宽度为 `2 / devicePixelRatio` 逻辑像素，两扇门各为 `1 / devicePixelRatio`。
- 验证门开启前底层仍被完整黑色遮罩覆盖，开启过程中门扇无透明度变化，结束后遮罩彻底卸载。
- 验证只有 `HomeScreen` 的最终遮罩播放双门，认证外层不产生重复开门。
- 验证减少动态效果下跳过退出运动。
- 运行新增目标测试、现有 splash 测试、完整 `flutter test` 与 `flutter analyze`，并与仓库当前已知失败清单按测试名比较，不能只比较失败数量。

### 本地视觉验收

- 在 Flutter 真实布局中截取归线开始、实体线、半开门和完成四个关键帧。
- 检查 iPhone 3× 屏幕下门边仍是两个物理像素总宽，且没有抗锯齿灰边、缝隙或一帧闪白。
- 检查社区主页在门后已完整布局，不在揭幕后继续发生整列跳动。
